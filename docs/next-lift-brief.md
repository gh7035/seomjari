# 섬자리 다음 개선 — 총괄 에이전트 지시서

이 문서는 현재 코드 기준의 다음 구현 지시서다. `docs/lead-agent-brief.md`의 Phase 1–4는 이미 반영되어 있다. 그 작업을 다시 하지 않는다. 사용자가 커밋을 말하기 전에는 커밋하지 않는다.

## 목표

이미 계산된 성수·비수 월을 결론과 신호에 드러내고, 모델 문장의 단위 없는 정수를 서버 값으로 막는다. 그다음 자연어로 의도만 고르는 계획 한 번과, 대안 지역의 관광·생존 비교를 붙인다. 종합 점수 공식과 신호 7개의 이름은 유지한다.

현재 내부 점수는 약 88/100이다. 이 문서의 Phase 1–2만 끝나도 약 90, Phase 3–4까지 끝나면 약 92다. 보장값이 아니다.

| 평가항목 | 배점 | 현재 | 이 문서 이후 |
|---|---:|---:|---:|
| 주제 타당성·창의성 | 15 | 13 | 14 |
| 필수 데이터 활용 | 20 | 18 | 18 |
| AI Agent 기술성·완성도 | 25 | 21 | 23 |
| 편의성·실용성 | 25 | 22 | 24 |
| 결과 신뢰성·재현성 | 15 | 14 | 15 |

데이터 항목은 그대로 둔다. D9를 지어 내거나 D6를 가중치에 넣지 않는다.

## 이미 되어 있는 것

- `LLM_PROVIDER=gemini`이면 `_run_llm`이 `_run_fallback`으로 도구를 실행한 뒤, 문장 호출은 1회다. 채택 필드는 `summary`와 대안 `why`뿐이다. `signals`, `score`, `evidence`, `limitations`, `map`은 모델 JSON을 병합하지 않는다.
- 안정형·애월읍·카페 종합 점수는 46이다. 유동은 7,632,789명, 3위/43, `as_of`는 `2018-01~2019-12`다. D6 근거는 2019년 순증 +684이고 점수 가중치에는 없다.
- 규칙 결론은 관광 의존도가 빨강이면 “관광 의존도 74.5% 때문에 성수기 착시 위험이 큽니다”를 포함한다.
- 채팅은 연령을 유지한다. 연령 라벨은 “수요 순위에만 반영. 유동에는 연령이 없음”이다. “선택 N개 남음”은 업종·지역만 센다.
- `pytest` 52개 통과가 마지막 확인 상태다. 구현 후 다시 통과해야 한다.

## 하지 말 것

- 모델에게 도구를 반복 호출시키지 않는다. `AGENT_MAX_TOOL_CALLS` 루프로 되돌리지 않는다.
- 종합 점수 가중치, 신호 7개 이름, D6를 점수에 넣는 변경을 하지 않는다.
- D9 입도객 숫자를 추정하지 않는다. 키가 없으면 “D9 입도객 없음”을 유지한다.
- 원본 CSV를 커밋하지 않고 `make data`를 돌리지 않는다.
- `.env`의 키를 문서나 로그에 적지 않는다.
- `openai`, `anthropic` 공급자를 구현하지 않는다.

## 확인된 빈틈

1. `packages/agent/tools.py` `get_demand`는 `peak_month`, `low_month`를 반환한다. 애월읍 카페는 8월과 12월이다. `packages/agent/signals.py` `compute_season`의 값은 `1.96배`이고 사유는 “최고월/최저월 매출 비율”이다. 월 이름이 신호와 결론에 없다.
2. `packages/agent/validation.py` `extract_numbers`는 `74.5%`, `1.96배`, `6위`, `3위/43`만 본다. `99점`, `순증 999`, `9월`은 걸러지지 않는다. `_sentence_ok`가 이 함수를 쓰므로, 배지는 46인데 문장만 99점일 수 있다.
3. 랜딩 질문은 `apps/web/src/App.tsx` `onEntrySubmit` → `/api/chat`이다. `apps/api/main.py` `chat()`이 토큰으로 지역·업종을 먼저 확정하고, 루프의 도구 순서는 여전히 고정이다. 업종·지역이 이미 확정된 진단에 계획 호출을 넣으면 대표 시나리오의 모델 호출이 1회에서 2회가 된다.
4. `compare_places`의 `ranking[].signals`는 이름→레벨 맵이다. 값 문자열이 없다. 대안 카드는 `일도2동 78점`과 `why`만 보인다. 관광 비중과 생존율을 나란히 보여줄 재료가 응답에 없다.

## Phase 1 — 성수월과 비수월을 문장에 넣기

점수 계산은 그대로 둔다. 보여주는 문자열만 바꾼다.

1. `compute_season`이 배율을 만든 그 월별 평균에서 최고월·최저월을 구한다. `value`를 `8월/12월 1.96배` 형태로 만든다. 월을 정할 수 없으면 지금처럼 `1.96배`만 둔다.
2. `_build_report`의 관광 의존도 빨강 문장 옆에 계절 월을 붙인다. 예: “관광 의존도 74.5%이고, 매출은 8월이 12월의 1.96배라 성수기 착시 위험이 큽니다.” 계절 신호가 없거나 월이 없으면 지금 문장을 유지한다.
3. 모델에 넘기는 `_narrative_payload`의 계절 신호 `value`에 월이 들어 있으므로, 모델 문장도 그 문자열만 인용할 수 있다. 월 숫자를 프롬프트에서 따로 지어 내게 하지 않는다.

변경 파일: `packages/agent/signals.py`, `packages/agent/loop.py`, `docs/results.md`의 계절 칸.

완료 기준:

- 안정형 애월읍 카페의 계절 신호 값에 `8월`과 `12월`과 `1.96배`가 있다.
- 종합 점수는 46이다.
- 규칙 결론 첫 문장에 `74.5%`와 `8월`과 `12월`이 있다.

## Phase 2 — 문장의 정수를 서버 값에 묶기

`extract_numbers`에 다음 토큰을 추가한다.

- `(\d+)점`에서 숫자
- `순증` 뒤의 `[+-]?\d+`
- `(\d{1,2})월`에서 월 번호

`_sentence_ok`는 이 토큰이 서버 payload·도구 요약·신호 값·점수·근거를 이어 붙인 문자열에 연속으로 있을 때만 통과시킨다. `99점`은 점수 46만 있으면 실패하고, 그 문장 전체는 버려서 규칙 문장으로 떨어진다. `8월`은 Phase 1 값에 `8월`이 있으므로 통과한다. `9월`은 그 월이 payload에 없으면 실패한다.

기존 비율·순위 패턴은 유지한다. 모델이 숫자 없는 문장을 쓰면 지금처럼 통과한다.

변경 파일: `packages/agent/validation.py`, `packages/agent/loop.py`의 `_sentence_ok` 사용처, `tests/test_grounding.py`.

완료 기준:

- 가짜 모델이 `summary`에 `99점`을 쓰면 채택되지 않고 규칙 문장이 나온다. 점수 필드는 46이다.
- 가짜 모델이 `8월`과 `74.5%`와 `46`만 쓰는 문장은 채택된다.
- 네일샵 예외 폴백의 `mode=partial`은 유지된다.

## Phase 3 — 비어 있는 자연어에만 계획 한 번

업종과 지역이 둘 다 확정된 진단은 지금처럼 도구 실행 후 문장 1회다. 계획 호출을 추가하지 않는다.

질문 때문에 업종 또는 지역이 비어 `parse_intent`가 `category_recommend`, `place_recommend`, `clarify`로 갈리는 경우에만, 도구 실행 전에 모델 호출 1회를 둔다.

출력은 JSON 하나만 허용한다.

```json
{"intent": "diagnose|place_recommend|category_recommend|clarify", "map_layer": "demand|tourism|supply|footfall|survival"}
```

`intent`가 목록 밖이거나 JSON이 아니면 지금 `parse_intent` 결과를 쓴다. 모델이 지역명·업종명·점수를 써도 무시한다. 지역·업종 문자열 해석은 기존 `resolve_place`, `resolve_category`만 한다. `map_layer`는 리포트의 `map.layer`를 덮어쓸 수 있되, 생존 리스크가 빨강이면 서버가 `survival`을 우선한다. 관광 의존도가 빨강이고 모델이 다른 레이어를 골라도 `tourism`을 우선한다. 둘 다 아니면 모델 레이어를 쓴다.

이 호출은 문장 호출과 별개다. 확정 진단의 모델 호출 횟수는 1회로 남는다. 빈 자연어 분기는 계획 1회 + 문장 1회까지다.

변경 파일: `packages/agent/loop.py`, `packages/agent/prompts.py`.

완료 기준:

- 안정형 애월읍 카페의 `chat_with_tools` 호출은 1회다.
- “성산에 뭐 하면 좋을까”에서 계획 호출이 실패해도 지금처럼 성산읍 빈틈 업종 리포트가 나온다.
- 계획 JSON의 점수를 99로 넣어도 리포트 점수는 서버 값이다.

## Phase 4 — 대안 카드에 관광과 생존

`compare_places`의 각 순위 항목에 신호 값 두 개를 추가한다. 키는 `tour_value`, `survival_value`이고, 내용은 그 동의 `score_risk` 신호 `value` 문자열이다. 신호가 `unavailable`이면 키를 생략한다.

`_build_report`의 `alternatives`에 이 두 값을 복사한다. 선택 지역의 같은 두 값은 이미 `report.signals`에 있다.

`apps/web/src/components/ReportCard.tsx` 대안 목록에서 점수 아래에 `관광 {선택값} → {대안값}`, `생존 {선택값} → {대안값}`을 적는다. 값이 없으면 그 줄은 그리지 않는다. 점수 순서는 `compare_places`의 내림차순을 유지한다.

변경 파일: `packages/agent/tools.py`, `packages/agent/loop.py`, `apps/web/src/types.ts`의 `Alternative`, `ReportCard.tsx`.

완료 기준:

- 안정형 애월읍 카페 대안의 첫 항목에 관광 값과 생존 값이 있고, 선택 지역 관광 74.5%보다 낮은 관광 값이 보인다.
- 종합 점수와 대안 점수 숫자는 Phase 4 이전과 같다.
- 프론트를 고친 뒤에는 `make build`로 `apps/api/static`을 갱신한다.

## 작업 순서

Phase 1 → Phase 2 → Phase 3 → Phase 4. Phase 1이 월 문자열을 만들어야 Phase 2의 `8월` 통과 조건이 성립한다. Phase 3은 대표 진단의 호출 횟수를 늘리지 않는지 테스트를 먼저 본다.

## 검증 체크리스트

- [ ] 안정형 애월읍 카페 점수 46, 계절 값에 8월·12월·1.96배, 결론에 74.5%와 그 월.
- [ ] 가짜 모델 `99점` 문장은 거절되고 규칙 문장이 나온다.
- [ ] 확정 진단의 모델 호출은 1회, 빈 자연어는 최대 2회.
- [ ] 성산읍 빈틈 업종 리포트는 계획 호출이 죽어도 나온다.
- [ ] 대안 카드에 관광·생존 값이 있고 점수 순위는 그대로다.
- [ ] D6는 근거 문장에만 있고 `weights`에 없다.
- [ ] `.venv/bin/pytest -q` 통과.
- [ ] Phase 4를 했으면 `make build` 후 한 줄 질문으로 지도와 점수 카드까지 확인한다.

## 완료 보고 형식

1. 바뀐 파일과 Phase.
2. 안정형 애월읍 카페의 계절 신호 값, 결론 첫 문장, 종합 점수.
3. `99점` 문장을 넣었을 때의 채택 여부.
4. 확정 진단과 “성산에 뭐 하면 좋을까”의 `chat_with_tools` 호출 횟수.
5. `pytest` 결과.
6. 하지 않은 것: 도구 반복 호출, D6 가중치, D9 추정, 다른 LLM 공급자.
