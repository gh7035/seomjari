# 섬자리 결과 설명자료

> 제주 AI·빅데이터 활용 AI Agent 개발 챌린지 개인 참가작

## 1. 문제 정의

| 지표 | 수치 | 출처 |
|---|---|---|
| 제주 신생률 | 20.0% (2016) → 12.4% (2025p) | KOSIS 기업생멸행정통계 |
| 숙박·음식점업 신생률 | 24.4% → 14.2% | 같음 |
| 제주 신생기업 생존율 | 1년 63.0%, 3년 48.9% | 국가데이터처 2025 |
| 청년 창업 대비 폐업률 | 95.8% (2023) | 한국은행 제주본부 |

**핵심 원인**: 내국인 관광 수요 감소 + 저진입장벽 업종 과당경쟁.

**사용자 불편**
1. 성수기만 보고 들어가 비수기에 매출이 무너진다 (성수기 착시).
2. 데이터가 흩어져 있어 무엇을 겹쳐 봐야 할지 모른다.
3. 기존 상권분석 도구는 지표만 주고 판단과 대안을 주지 않는다.
4. 관광객과 도민을 구분해 보는 제주 특화 분석이 없다.

## 2. Agent 구조

```
사용자 입력 폼 + (선택) 자연어
          │
    ┌─────▼─────┐
    │   Loop    │  ① 의도 파악 → ② 계획(상태만) → ③ 도구 실행 → ④ 검증 → ⑤ 리포트
    │ (SSE 발행) │
    └─────┬─────┘
          │
   resolve_place / resolve_category / get_demand / get_supply
   get_footfall / get_survival / get_recent_openings / score_risk
   compare_places (🔴 2개 이상 또는 지역 미지정)
          │
          ▼  (parquet 11종, pandas)
   data/processed/
```

등록 도구는 16개다. 계획 단계는 이번에 호출할 도구 이름을 SSE로 먼저 보낸다.

**실행 모드** (`LLM_PROVIDER`)
- `none` (기본): 고정된 규칙 루프. 수치는 결정론적이다.
- `gemini`: function-calling. 스키마·그라운딩 검증에 실패하거나 도구 호출이 상한에 닿으면 규칙 루프로 떨어지고, 리포트 `mode`가 `llm_fallback`이 되어 화면 각주가 나온다.
- `openai`, `anthropic`: `packages/agent/llm.py`가 미구현 예외를 내고 규칙 루프로 떨어진다.

**자율 수행 범위**
- 규칙 루프가 하는 일: 지역·업종 해석, 고정된 도구 순서, 빨간 신호가 2개 이상이면 `compare_places`.
- `category_recommend`이면 `find_gap_category`로 빈틈 업종 리포트를 만든다. 폼에서 지역만 고르고 질문은 없으면 업종을 되묻는다.
- Agent가 하지 않음: 데이터에 없는 수치 생성, 성공 단정, 모호한 업종을 추측해 진행.

## 3. 주요 기능

| 기능 | 경로 | 상태 |
|---|---|---|
| 사전 정보 폼 (업종 16 / 지역 / 주 고객 / 타깃 연령 / 리스크) | `ContextPanel.tsx`, 랜딩은 `Entry.tsx` | ✅ |
| Agent 진행 단계 실시간 표시 (SSE) | `apps/api/main.py` | ✅ |
| 신호 7개 + 종합 점수 + 근거·한계 카드 | `ReportCard.tsx`, `packages/agent/signals.py` | ✅ |

| 대안 지역 Top 3 | `compare_places` | ✅ |
| 후속 채팅 | `/api/chat` | ✅ |
| 업종 트렌드 (지역 점수에는 미포함) | `get_trend` | ✅ |

타깃 연령을 고르면 수요 규모만 `demand_age`로 다시 순위를 매긴다. 유동 데이터에는 연령 열이 없어 사유에 "연령 미적용"이 붙는다. `DiagnoseForm.tsx`는 남아 있으나 앱은 `ContextPanel`을 쓴다.

### S2 · 카페 · 지역 없음 · 도민 · 균형

`compare_places`와 `get_trend`를 호출한다. 대상 지역 점수는 null이다. Top 3는 **일도2동 78, 화북동 75, 이도2동 71**이다. 안정형 점수와 가중치가 달라 이도2동 점수가 72가 아니다.

### S3 · "성산에 뭐 하면 좋을까"

성산읍의 빈틈 업종 리포트를 낸다. 업종 선택지로 되묻지 않는다. 지도는 1순위 업종으로 성산읍을 강조한다.

### S4 · 애월읍 · 업종 없음

되묻기: `'애월읍' 지역에서 어떤 업종을 검토할지 선택해 주세요.` 리포트는 나오지 않는다.

### S5 · 매핑 밖 업종과 부분 업종

- `자동차 정비소`는 매핑 밖이다. S4와 같이 업종을 되묻고 리포트는 없다. `tests/test_grounding.py`의 S5가 이 경우다.
- `네일샵`은 매핑된 업종이다. 애월읍 기준 가용 신호 2/7 (유동 🟢, 경쟁 12개 점포 🟡), 점수 null, confidence `low`, mode `partial`. D1·D5가 없다.

### 후속 채팅 (`/api/chat`)

- 질문에 지역이 있으면 그 지역으로 바꾸고, 업종이 없으면 직전 업종을 유지한다. "그럼 한림은 어때?"는 카페를 유지하고 한림읍으로 다시 진단한다.
- 업종만 있으면 직전 지역을 유지한다. "한식당은 어때?"는 같은 동의 한식당 재진단이다.
- 주 고객과 리스크 성향은 직전 값을 유지한다. 연령은 빈 배열로 다시 시작한다.

## 5. 검증 & 한계

**테스트** (`LLM_PROVIDER=none` 기준 `pytest` 47개)
- `tests/test_grounding.py`: S1 3회 재현, 리포트 수치가 도구 출력에 있는지, S2 지역 추천, S4·S5(자동차 정비소) clarify.
- `tests/test_intent_partial.py`: PC방·미용실처럼 D4만 있는 업종의 partial과 점수 보류.

**데이터 한계**
1. 지역별 카드 데이터는 2021-05까지. 지표 계산 창은 2018-01~2019-12.
2. 카드사 표본일 수 있어 화면은 비중·배율·순위 중심이다.
3. 업종은 16개로 매핑한다. 카드 매출이 있는 11개만 수요·관광·계절이 나오고, PC방·미용실·네일샵·헬스장·노래방은 점수를 보류한다. 매핑 밖은 업종을 되묻는다.
4. 경쟁 점수는 2025-09 점포수 백분위다. 2018~2019 매출로 나눈 점포/억원 비율은 사유에만 적는다.
5. 유동 수요는 업종과 무관한 방문인구다.

## 6. 센터 활용 방안

1. **지원사업 심사 보조**: 신청 업종·지역으로 리포트를 만들어 관광 의존도·생존·개폐업을 같이 본다.
2. **정책 데이터 백본**: `data/processed/` parquet (D1~D6 산출물)을 분석가가 재사용한다.
3. **공급 모니터링**: `compare_places`·`get_supply`로 과공급 동을 본다. 애월읍 카페는 점포 225개, 업종 내 1위다.
4. **D3 트렌드**: `get_trend`가 2018년 대비 최근 연도 증감을 리포트 문장으로 붙인다. 지역 점수에는 더하지 않는다.
5. **품질 메모**: D1 `매장수`는 시 단위라 쓰지 않고, 점포 수는 D4로 센다.

## 7. AI 활용 고지

**서비스 내 AI 모델**
- 기본: 규칙 기반 루프. 수치는 `packages/agent/signals.py`와 `tools.py`에서 계산한다.
- 구현된 외부 모델은 Gemini뿐이다. 센터 PC는 로컬 LLM을 돌리지 않는다 (VRAM 3GB).

**개발 과정 AI 도구**
- Anthropic Claude 코드 어시스턴트로 파이프라인·루프 초안을 작성하고, 수치 검증은 `tests/`로 한다.
